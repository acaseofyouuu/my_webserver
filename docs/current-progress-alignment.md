## 本轮具体修改

此前 `/` 返回最初的 Hello 学习页面；原版 `/` 返回 `judge.html`，让用户选择注册或登录。
现在 `/` 返回自己的 `judge.html`，原来的 `index.html` 文件与内容保留，可通过首页链接访问。

| 操作 | 原版使用的地址 / 字段 | 本轮对齐后的结果 |
| --- | --- | --- |
| 首页选择新用户 | POST `/0` | 返回已有注册表单 |
| 首页选择已有账号 | POST `/1` | 返回 `log.html` 登录表单 |
| 提交注册 | POST `/3CGISQL.cgi`，`user`、`password` | 调用已有注册代码，成功后直接显示登录表单 |
| 提交登录 | POST `/2CGISQL.cgi`，`user`、`password` | 调用已有密码验证和会话代码，成功后显示 `welcome.html` |
| 注册或登录失败 | 显示失败页面 | 继续使用已实现的重复用户名、密码错误页面 |
| 登录后选择操作 | `welcome.html` | 本阶段只展示已经实现的个人页面、学习页面入口 |

`/0`、`/1` 也接受 GET；`/2`、`/3` 分别作为原版登录、注册提交地址的别名。
`/logError.html`、`/registerError.html` 映射到现有错误页。
这些地址中的 `.cgi` 是路由名字，本阶段没有引入执行 CGI 程序的功能。

在 `HttpConnection::handle()` 中，原版提交地址先映射到已有 `/login`、`/register` 分支。
根据入口选择用户名字段 `user` 或 `username`，随后仍调用相同的 `AccountRepository`。
因此不是另造一套注册、登录或数据库。

## 保留的进度

- 原来的 POST `/register`、POST `/login` 继续接收 `username`、`password`，返回原有成功页面。
- `/index.html`、`/about.html`、`/contact.html`、CSS、400/404/405/500 错误处理保留。
- 原有 `accounts` 表及账号不迁移、不删除。仍使用参数化 SQL 和 PBKDF2-SHA256 哈希。
- 会话 Cookie、`/profile` 权限检查、POST `/logout` 保留，且原版入口也使用同一套会话。
- keep-alive、线程池、epoll、空闲回收、同步日志、数据库连接池、启动参数和停止收尾不重写。
- 保留已经学过的文件组织与类名，便于继续理解自己的代码。

## 明确保留的差异

这里的“对齐”指当前阶段对应的功能和操作流程，不是逐字节模仿原版所有响应。

- 注册成功仍返回 201，用户名重复仍返回 409，账号密码错误仍返回 403；原版常用 200 返回这些结果页面。
- 密码保留 8～128 字节注册规则；登录时短密码依然按验证失败处理。原版没有相同的密码规则。
- `/welcome.html` 和原版一样是公开的选择页面，不承担权限验证；个人页面的权限仍在 `/profile` 检查。
- 默认端口仍为 8080，线程数及数据库连接数仍为 4，空闲超时仍为 10 秒。原版的默认配置不同。
- 原版的非阻塞事件处理、状态机等尚未完成，不能把当前实现说成原版全部机制已经复刻。
